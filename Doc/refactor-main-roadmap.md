# 大規模リファクタ方針

## 目的

現状と同一動作を維持しつつ、ATS本体を責務ごとに分割し、将来のSocket通信追加に耐える構造へ寄せる。

## ブランチ運用

- `codex/refactor-main`: 大規模リファクタ全体の受け皿。
- `codex/refactor-*`: 個別PR用ブランチ。原則として `codex/refactor-main` 向けにPRを作る。
- 既存動作を保つため、各PRはビルド可能な小単位に分ける。

## 分割方針

- 通信部: 認証、接続実装、送受信DTO生成、再接続制御を分ける。
- 車上装置部: `CableIO` が束ねているLED、継電、検査記録、告知器連携を段階的にサービスへ分ける。
- 表示部: WinFormsイベント処理と表示ロジックを分け、再描画頻度や画像生成の無駄を減らす。
- TrainCrew連携: WebSocket入出力、コマンドキュー、反射コピー処理を分ける。

## Socket通信を見込んだ設計

最初に `IServerConnection` を境界として作る。現行SignalRは `SignalRServerConnection` に閉じ込め、将来のSocket通信は同じ境界を実装する。

これにより、上位の `Network` は「ATSデータを送る」「サーバーデータを受ける」という意味だけを扱い、通信方式の差を持たない。
